# 3D施設案内ウォークスルーシステム 技術仕様書

## 1. システム概要

360度パノラマ画像を用いた施設内ウォークスルー（バーチャルツアー）システム。
ユーザーは全天球パノラマ内を視点操作しながら、経路上のホットスポット（リンク）をクリックすることで隣接する空間へ「歩いて」移動できる。移動先候補は3D空間内にルートライン・案内テキスト・ピンとして描画され、画面右上のミニマップにも現在地・フロア・経路が同期表示される。

**主な技術要素**
- Three.js（r128）による360度パノラマ描画・視点制御
- SVGベースのミニマップ（パン・ズーム・フロア切替・ダブルクリックでのテレポート）
- JSON形式のノード・リンクデータによるグラフ構造のマップ管理
- HUD設定モーダルによる表示要素のON/OFF切替

**ファイル構成と役割分担**

| ファイル | 役割 |
|---|---|
| `mapData.js` | マップのデータモデル定義・JSON読み込み・座標／リンク計算 |
| `main.js` | Three.jsによる3Dパノラマ描画・視点操作・移動演出・アニメーションループ |
| `minimap.js` | SVGミニマップの生成・描画・操作（パン/ズーム/フロア切替/テレポート） |
| `index.html` | DOM構造・HUDレイアウト・設定モーダル・スクリプト読み込み順の定義 |

**読み込み順序（`index.html`）**
```
mapData.js → minimap.js → main.js
```
実際の初期化トリガーは `main.js` 内の `DOMContentLoaded` イベントが担い、以下の順序を保証している。
```
initMapData()（JSON読込・グラフ構築）
  → initMinimapLayout()（ミニマップSVG生成）
  → loadInitial()（初期ノードのパノラマ表示・ミニマップ同期）
  → requestAnimationFrame(animate)（描画ループ開始）
```

## 2. mapData.js — データモデル・マップグラフ管理

### 2.1 クラス構成

#### `PanoramaAsset`
ノードに対応するパノラマ画像のURLを構築する。
- `building`（North/Main/South）と `floor`（階数）から、画像フォルダパス（例: `北館3F/`）を自動生成
- 画像未指定時は既定の `entrance.jpg` にフォールバック

#### `MapNode`
1つの視点（部屋・廊下等）を表すノード。

| プロパティ | 内容 |
|---|---|
| `id` | ノード一意識別子 |
| `name` / `sub` | 表示名・サブ情報（HUDロケーション表示に使用） |
| `asset` | `PanoramaAsset` インスタンス（画像URL） |
| `initYaw` | テレポート時の初期視線方向 |
| `pos3D` | 絶対空間座標 `[x, y, z]` |
| `floor` / `building` | 所属フロア・棟 |
| `mmX` / `mmY` | ミニマップSVG上の座標（`calcMinimapCoords`で算出） |
| `links` | 隣接ノードへの接続情報配列 |

#### `MapGraph`
全ノードを管理し、複数JSONの統合・座標計算・リンク解決を行う。

| メソッド | 処理内容 |
|---|---|
| `loadFromMultipleJSON(jsonArray)` | 複数JSONの `nodes` をマージして `MapNode` を生成し、以下を順次実行 |
| `calcMinimapCoords()` | `pos3D` の X/Z 座標に固定スケール（3.0倍）を掛け、ミニマップSVG座標 `mmX/mmY` を算出 |
| `buildAllLinks()` | 各ノードの `links` に対し、接続先ノードとの相対ベクトル（差分座標）`link.pos` を自動計算（未接続時は既定値 `[0,0,-10]`） |

### 2.2 データフロー
`main.js` の `initMapData()` が北館・本館・南館 × 1〜4Fの計12個のJSONファイル（`../data/*.json`）を並列fetchし、`mapGraph.loadFromMultipleJSON()` に渡してグラフを構築。結果は `window.NODES` としてグローバル公開され、`main.js` / `minimap.js` の両方から参照される。

> **備考**：旧実装では単一の `mapData.json` を読み込む `loadMapData()` 関数が存在したが、現行のフロア別JSON方式に統一されたため、現在はコメントアウトされ未使用。

## 3. main.js — 3Dパノラマ描画・視点制御

### 3.1 シーン構成

- **二重スフィア方式**によるパノラマ切替演出
  - `sphereA`：現在表示中のパノラマ（不透明、テクスチャあり）
  - `sphereB`：遷移先パノラマ（移動演出中にフェードイン、待機中は透明）
  - 各スフィアに付随して、デバッグ用のワイヤーフレーム（`gridEdgesA/B`）と頂点ポイント（`gridPointsA/B`）を保持し、設定パネルからON/OFF可能
- **ルートラインオブジェクト群**（`routeLinesGroup`）
  - `buildRouteLines(node)` がノード切替のたびに再構築
  - 各リンクごとに「経路プレーン（半透明の帯）」「行き先テキスト（Canvasテクスチャによる動的スプライト）」「矢印ピン（ShapeGeometry）」の3要素を生成
- **オービタルデバッグモニター**（画面内の俯瞰カメラビュー）
  - `debugOrtho`（正射影）/ `debugPersp`（透視投影）を `0`キーで切替、`1/2/3`キーで視点プリセット切替、ホイールでズーム
  - 設定パネルでOFFの場合、当該レンダリングパス自体をスキップ（後述の負荷対策）

### 3.2 状態管理（主なグローバル変数）

| 変数 | 内容 |
|---|---|
| `currentId` / `nextId` | 現在ノードID／移動先ノードID |
| `yaw`, `pitch`, `tYaw`, `tPitch` | 現在の視線角度と目標角度（イージングで追従） |
| `fov`, `tFov` | 現在・目標画角（ズーム操作用） |
| `walkPhase` | `'idle' / 'walk' / 'settle'` の状態遷移 |
| `uiConfig` | エッジ・頂点・ルート表示や案内テキストサイズモードのUI設定 |
| `isDebugMonitorOn` | デバッグモニター表示状態（負荷制御に使用） |

### 3.3 主要関数

| 関数 | 処理内容 |
|---|---|
| `buildRouteLines(node)` | 現在ノードのリンクから経路描画オブジェクトを再生成 |
| `startWalk(targetId, hotspotPos)` | 移動アニメーション開始。遷移先テクスチャを非同期ロードしつつ`sphereB`へ適用 |
| `finishWalk()` | 移動完了処理。`sphereA`⇔`sphereB`の入れ替え、HUD・ミニマップ更新 |
| `loadInitial(nodeId)` | 起動時の初期ノード読み込み・表示 |
| `updateCamera()` | yaw/pitchから注視点を計算しカメラに反映 |
| `animate(now)` | メインアニメーションループ（後述） |

### 3.4 入力操作

| 操作 | 内容 |
|---|---|
| ドラッグ / タッチスワイプ | 視線方向（yaw/pitch）操作 |
| ホイール / ピンチ | FOV（ズーム）操作 |
| ダブルクリック | ルートライン上のヒット判定→`startWalk()`で移動 |
| ポインター移動（非ドラッグ時） | Raycastによるホバー判定、ツールチップ表示 |

### 3.5 アニメーションループ（`animate`）の処理分岐

1. **`walkPhase === 'walk'`（移動演出中）**
   - `walkT` を時間経過で進行（`WALK_DUR`＝1.1秒）
   - `walkDir` を軸とした非一様スケーリング行列で `sphereA` を圧縮変形させる「吸い込まれる」演出（★詳細は3.5.1）
   - `walkT >= 0.9` でクロスフェード開始、`walkT >= 1` で `finishWalk()` 呼び出し
2. **`walkPhase === 'idle'`（通常時）**
   - yaw/pitch/fovを目標値へイージング追従
   - ルートラインの不透明度・スケール（距離に応じた文字サイズ調整）を更新
3. **共通処理**
   - メインレンダリング（`renderer.render`）
   - デバッグモニターON時のみ、ワイヤーフレーム切替＋2回目のレンダリング（`debugRenderer.render`）を実行

### 3.5.1 スフィア変形行列 — 移動方向へ「吸い込まれる」演出（本システムのコア技術）

移動演出の最大の特徴は、単純な2枚のパノラマ間のクロスフェードではなく、**現在のスフィア形状そのものを移動方向へ非一様に圧縮変形させる**ことで、進行方向へ吸い込まれていくようなワープ感を作り出している点にある。

**数学的原理**

進行方向の単位ベクトルを `n = (nx, ny, nz)`（＝`walkDir`）、その方向への圧縮スケール係数を `s` とすると、「`n` 方向のみを `s` 倍に縮小し、それに直交する平面方向は等倍のまま保つ」変換行列 `M` は、恒等行列 `I` と `n` の自己テンソル積（外積）`n nᵀ` を用いて次のように表せる、いわゆる**任意軸方向スケーリング（directional / axis scaling）**の公式である。

```
M = I + (s − 1)·(n nᵀ)
```

3×3成分に展開すると：

```
        | 1+(s-1)nx²   (s-1)nxny    (s-1)nxnz |
  M  =  | (s-1)nynx    1+(s-1)ny²   (s-1)nynz |
        | (s-1)nznx    (s-1)nzny    1+(s-1)nz² |
```

`main.js` の実装ではこの式がそのまま `THREE.Matrix4().set(...)` の16成分として展開・コーディングされている。

**パラメータの意味**

| 記号 | 対応する変数 | 意味 |
|---|---|---|
| `n` | `walkDir` | クリックされたホットスポット座標を正規化した、移動先方向の単位ベクトル |
| `s` | `1.0 − 0.85 × walkT` | 圧縮係数。`walkT`（0→1）の進行に伴い `1.0 →	 0.15` まで単調減少 |
| `walkT` | `walkT` | 移動演出の進行度（0〜1、`WALK_DUR`=1.1秒で正規化した経過時間） |

**視覚的な効果（時系列）**

| walkT | s | 見え方 |
|---|---|---|
| 0.0 | 1.0 | 無変形。通常のパノラマ球のまま静止 |
| 0.0→0.9 | 1.0→0.235 | 進行方向 `n` の軸だけがスフィアを最大約85%まで圧縮。進行方向にある空間だけが手前に引き寄せられるように歪み、ワープ感を演出（同時に `hud-speed` の「WARPING」表示が出現） |
| 0.9→1.0 | 0.235→0.15 | 圧縮変形を保ったままクロスフェード開始。変形しきったスフィアAが透明化し、遷移先スフィアBが実寸大で出現 |
| 1.0 | — | `finishWalk()` によりスフィアA/Bの役割が入れ替わり、変形はリセットされる |

**実装上の工夫**

- `sphereA.matrixAutoUpdate = false` により Three.js の自動TRS（Translation/Rotation/Scale）合成を無効化し、`matrix` プロパティへ直接この変形行列を書き込むことで、標準の `scale` プロパティでは表現できない「任意軸に沿った非一様スケーリング」を実現している
- 遷移先スフィア `sphereB` 側は変形させず、恒等に近い `flipMatrix` のみを適用。「変形して消えていく現在地」と「等倍のまま現れる目的地」を2枚のスフィアに役割分担させることで演出の対比を作っている
- 移動演出終了時（`finishWalk()`）に `matrixAutoUpdate = true` へ戻し、`scale`/`quaternion` を明示的にリセットすることで、次回の移動時にも同じ行列計算をクリーンな状態から適用できるようにしている

### 3.6 パフォーマンス対策（実施済み）

- テクスチャのミップマップ自動生成を無効化（`generateMipmaps=false` / `minFilter=LinearFilter`）し、パノラマ切替時の同期処理スパイクを解消
- デバッグモニター非表示時は二重レンダリング・マテリアル状態切替を完全スキップ

## 4. minimap.js — SVGミニマップ

### 4.1 構築処理

`initMinimapLayout()` が起動時に一度だけSVG DOM（グリッド背景／フロア画像／ノード円・エッジ線／プレイヤーアイコン／ズームボタン／フロア切替ボタン等）を動的生成する。ノード・エッジは全フロア分を生成した上で、`updateMinimapFloor()` により該当フロアのみ `display` 制御で表示切替する方式。

### 4.2 主要関数

| 関数 | 処理内容 |
|---|---|
| `initMinimapLayout()` | SVG要素一式を生成しDOMに挿入、インタラクションを初期化 |
| `updateMinimapFloor(floorNumber)` | フロア切替。背景画像・タイトル・ノード表示・フロアボタンの色分けを更新 |
| `updateMinimap()` | 現在ノードに応じたフロア表示・ノード色・トランスフォーム更新 |
| `applyMinimapTransform()` | パン/ズーム値をSVGのtransformへ反映。移動演出中は現在地アイコンを補間移動 |
| `focusCurrentNodeOnMinimap()` | 現在ノードを中心にミニマップをオートフォーカス |
| `setupMinimapInteractions()` | ドラッグパン、ホイール/ボタンズーム、ダブルクリックテレポート、フロアボタンのイベント登録 |

### 4.3 テレポート機能（ダブルクリック）

ミニマップ上でダブルクリックした座標に最も近いノード（同一フロア、閾値100px以内）を検出し、確認モーダルを表示。「はい」選択で `loadInitial()` を呼び出し、パノラマ経由の移動演出を挟まず直接ワープする。

### 4.4 main.jsとの連携ポイント

- `window.NODES`（`mapData.js`が生成）を共有データソースとして参照
- `main.js` 側の `walkPhase` / `yaw` / `currentId` / `mmSrcNode` を参照し、移動演出中のプレイヤーアイコン位置・向きをリアルタイム同期
- `main.js` の `animate()` ループから `updateMinimapPulse()` が毎フレーム呼ばれるが、現状パルス表現はSVGの `<animate>` タグに委譲しているため処理は空

## 6. 今後の検討事項（メモ）

現時点で議論中・未着手の追加最適化候補：
- CameraHelperのメインレンダーパスからの除外（デバッグOFF時）
- 非表示要素の `visible=false` 化による描画コール自体の削減
- 全球スフィアの分割数見直し（60×60→軽量化、見た目とのトレードオフ）
- `devicePixelRatio` 上限の調整（モバイル負荷対策、見た目とのトレードオフ）
- パノラマ画像アセット自体の解像度・圧縮最適化
